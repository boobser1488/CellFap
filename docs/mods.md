# Модификации CellFap

Модификация может:

- **скриптом на dypt** (`mod.dpt`) добавлять геномы и программы, следить за чашкой и менять её — клетки, пищу,
  условия; скрипт работает в песочнице;
- **нативным кодом** (`native/…`) — библиотекой на любом языке с C ABI (C, C++, Rust, Zig, Go, Odin, Nim, Pascal…) —
  работать со всей игрой: менять поведение клеток и физику, получать рождения и гибели, показывать свою панель и
  рисовать поверх чашки. Такой код запускается **только с разрешения игрока**;
- **шейдерами** (`shaders/…`) заменять, как рисуются чашка, клетки, связи и частицы;
- приносить **файлы** (`assets/…`): геномы, программы, текстуры, звуки, данные — их читают скрипт и нативный код;
- показывать **картинку** (`preview.png`) в окне «Модификации».

Модификации включают, выключают и настраивают в окне **«Модификации»**: меню «Окна» или «Настройки» →
«Открыть «Модификации»».

> В игре «моды» уже означают режимы клеток в редакторе генома, поэтому окно называется «Модификации».

## Где лежат и как устроены

Папка `mods` рядом с игрой (на телефоне — в данных приложения). Каждая модификация — либо папка, либо один файл
`.cfmod`:

```
mods/
  example/                 папка: удобно писать и править
    mod.txt                описание и настройки (обязателен)
    mod.dpt                скрипт (необязателен)
    preview.png            картинка для окна (необязательна)
    native/
      windows-x64/mod.dll              нативный код для Windows
      android-arm64-v8a/libmod.so      … и для телефона
    shaders/
      cell.frag            исходник GLSL (необязателен)
      cell.frag.spv        скомпилированный SPIR-V — его и загружает игра
    assets/                любые файлы модификации
      alga.genome.txt
  friend.cfmod             то же самое одним файлом
```

**`.cfmod` — обычный ZIP-архив** (с переименованным расширением). Его можно собрать любым архиватором и открыть,
чтобы посмотреть, что внутри: `mod.txt` должен лежать в корне архива (или в единственной папке верхнего уровня —
так получается, если заархивировать саму папку мода). Поддерживаются записи без сжатия и deflate, имена в UTF-8;
зашифрованные, многотомные архивы и ZIP64 отвергаются. Пути с `..`, абсолютные пути и диски отвергаются вместе со
всем архивом. Пределы: 512 файлов и 64 МБ в распакованном виде. Самые первые пакеты (формат `CFMOD1`, жили один
день) по-прежнему читаются.

При первом запуске игра кладёт в `mods/example` пример (выключенный). Файл `.cfmod` можно открыть игрой («Открыть
файл…», «Поделиться» на телефоне, кнопка «Добавить .cfmod…» в окне) — он скопируется в `mods` выключенным: чужую
модификацию запускаете вы сами.

Две модификации с одним `id` (например, папка и её же пакет) не запускаются обе: вторая по алфавиту помечается
дубликатом и не включается, пока одну из них не убрать.

### preview.png

Картинка показывается в списке (маленькой) и в подробностях (крупнее). PNG: 8-битные серые, серые с прозрачностью,
RGB, RGBA и палитровые (1–8 бит), без чересстрочной развёртки, не больше 1024×1024. Разумный размер — 128×128 или
256×256. Если картинку не удалось прочитать, в окне написано почему.

### assets/

Любые файлы. Скрипт читает их через `файл_мода(путь)`, нативный код — `api->mod_file(mod, путь, &данные, &размер)`.
Путь можно писать от корня модификации (`"assets/alga.genome.txt"`) или короче — без `assets/` (`"alga.genome.txt"`):
игра ищет сначала как написано, потом в `assets/`. Так же ищут `добавить_геном`, `добавить_программу` и
`добавить_клетку`.

## mod.txt

Строки «ключ значение», `#` — комментарий. Метка порядка байтов UTF-8 (BOM), которую ставит Блокнот, не мешает.

| Ключ | Что это |
| --- | --- |
| `id` | имя для `settings/mods.ini` (буквы, цифры, `_`, `-`); обязателен и должен быть уникальным |
| `name` | название в окне; обязателен |
| `version`, `author` | для окна |
| `description` | описание; несколько строк `description` склеиваются |
| `tick N` | вызывать `тик()` скрипта каждые N тиков симуляции (400 тиков — час игрового времени); без строки — не вызывать |
| `native <файл>` | какая библиотека в `native/<платформа>/` главная, если их там несколько |
| `setting …` | настройка, которую игрок меняет в окне (ниже) |

Настройки:

```
setting <ключ> число <по умолчанию> <мин> <макс> <подпись>
setting <ключ> флаг  <0|1> <подпись>
setting <ключ> выбор <по умолчанию> <вариант,вариант,...> <подпись>
```

Число с целыми границами показывается целым ползунком и приходит в скрипт целым (`int`) — его можно ставить в
`for k = 1 to n`. Значения, которые игрок поменял, сохраняются в `settings/mods.ini`. Ключ настройки не может
содержать `=`, `[`, `]`, `#`, `;` и называться `enabled` или `native_sha256` (это строки самого `mods.ini`); числа
должны быть числами (не `inf`, не `nan`).

## Скрипт mod.dpt

### Точки входа

Все необязательны.

| Функция | Когда |
| --- | --- |
| `загрузка()` | один раз при включении: добавить геномы и программы, подготовить своё состояние |
| `тик(состояние)` | каждые `tick` тиков; `состояние = [часы, клеток, пищи, тик]` |
| `настройки_изменены()` | игрок поменял настройку в окне |
| `новая_чашка()` | чашку заменили: новый опыт, открытый файл, уровень |
| `выгрузка()` | при выключении |

Переменные верхнего уровня файла живут, пока модификация включена (присваивание внутри функции меняет глобальную
переменную, если она уже задана наверху файла).

### Функции игры

| Функция | Что делает |
| --- | --- |
| `журнал(...)` | строка в журнал модификации (окно «Модификации»); доводы подряд, как `print` — он тоже пишет в журнал |
| `сообщение(текст)` | всплывающее сообщение на экране |
| `настройка(ключ)` | значение настройки: число, `true`/`false` или выбранный вариант строкой |
| `файл_мода(путь)` | текст файла модификации (см. «assets/») |
| `случайное()` | число от 0 до 1 |
| `добавить_геном(название, файл)` | только в `загрузка()`: геном (файл `.genome.txt` или сам текст генома) — в браузере геномов, вкладка «Модификации» |
| `добавить_программу(название, файл)` | только в `загрузка()`: программа сигнальной клетки (файл `.dpt` или текст) — в редакторе программ, «Вставить пример» |
| `сохранить_чашку(имя)` | сохранить чашку в `substrates/<имя>.substrate` (после вызова) |
| `открыть_чашку(имя)` | открыть `substrates/<имя>.substrate` (после вызова) |

#### Чашка целиком

Доступны в `тик()`, `настройки_изменены()` и `новая_чашка()`.

| Функция | Что делает |
| --- | --- |
| `узнать(имя)` | `часы`, `клеток`, `пищи`, `тик` и любой параметр чашки (таблица ниже) |
| `задать(имя, значение)` | параметр чашки (значение ограничивается диапазоном) |
| `добавить_пищу(x, y, масса?)` | порция пищи в точке (мкм от центра чашки), масса 0.01–2 (по умолчанию 0.3); до 500 за вызов |
| `ячеек()` | сколько номеров клеток (живые и пустые): клетки — это `0 … ячеек()-1` |
| `клетка(i)` | клетка списком или `null`, если номер пуст (поля ниже) |
| `клетки_рядом(x, y, r)` | номера живых клеток в круге (по сетке прошлого тика; до 4096) |
| `соседи(i)` | номера клеток, связанных с клеткой `i` адгезином |
| `пища(i)` | порция `i` (`0 … узнать("пищи")-1`): `[x, y, масса]` или `null` |
| `изменить_клетку(i, поле, значение)` | `x`, `y`, `vx`, `vy`, `угол`, `масса`, `возраст`, `азот`, `повреждение`, `режим`, `s1` … `s8` |
| `убить_клетку(i, пища?)` | клетка погибает (по умолчанию оставляя пищу) |
| `добавить_клетку(геном, x, y, угол?, режим?)` | новая клетка: `геном` — название генома, добавленного этой модификацией, файл модификации или текст генома |
| `убрать_пищу(i)` | убрать порцию |

`клетка(i)` возвращает список: `[0 id, 1 x, 2 y, 3 vx, 4 vy, 5 угол, 6 масса, 7 радиус, 8 возраст, 9 азот,
10 повреждение, 11 тип, 12 режим, 13 связей, 14 геном, 15 [S1 … S8]]`. Тип — номер типа клетки (как
`CELLFAP_<ТИП>` в `sdk/cellfap_mod.h`: 0 фагоцит, 1 жгутиковая, 2 фотоцит…). Скорость — мкм за тик.

```dypt
function тик(с) {
    for i in клетки_рядом(0, 0, 100000) {
        к = клетка(i)
        if к != null and к[6] < 1.0 {
            изменить_клетку(i, "масса", к[6] + 0.01)   // подкормить худых
        }
    }
}
```

Пока скрипт работает, он **читает** живую чашку, а всё, что он **меняет**, игра собирает и применяет после того,
как функция вернулась, — по порядку; клетку, которая за это время погибла, изменение не трогает. Скрипт, который
завис, отрезается от чашки раньше, чем игра идёт дальше.

| dypt | C API | Диапазон |
| --- | --- | --- |
| `свет` | `light` | 0–2 |
| `питание` | `nutrient_rate` | 0–15 (скорость появления пищи) |
| `радиация` | `radiation` | 0–0.09 |
| `вязкость` | `viscosity` | 0–150 |
| `гравитация` | `gravity` | 0–1 |
| `солёность` | `salinity` | 0–1 |
| `нитраты` | `nitrates` | 0–1 |
| `день` | `day_length` | 0–48 (длина суток в часах, 0 — вечный день) |
| `направление_света` | `light_angle` | радианы |
| `радиус` | `dish_radius` | только узнать |
| `предел_клеток`, `предел_пищи` | `max_cells`, `max_food` | 1–200000, 0–200000 |
| `крышка`, `заражение`, `смерть_у_края`, `точечные_мутации`, `старение`, `подвижная_пища` | `lid`, `contaminate`, `kill_at_edge`, `only_point_mutations`, `cell_aging`, `mobile_food` | 0 / 1 |

| `разброс_света`, `вращение_света`, `ёмкость_света` | `light_range`, `light_dir_change`, `light_capacity` | 0–1, 0–1, 0.02–1 |
| `плотность`, `градиент_плотности` | `density`, `density_gradient` | −3.3–3.3, −2–0 |
| `анизотропия`, `травмы`, `сок` | `swim_anisotropy`, `mechanical_damage`, `sap_leak` | 1–6, 0–1, 0–2 |
| `физика_cell_lab`, `режим_гиалуроновой` | `cell_lab_physics`, `hyaluronic_mode` | 0 / 1, 0–2 |

### Ограничения скрипта

- Нельзя: `import`, `extern`, `from`, работа с файлами (`read`, `write`, `append`, `exists`), внешние библиотеки
  (`load_bin`, `call_bin`, `call_at`), память (`malloc`, `raw_*`, `peek`, `poke`, `mem_*`), потоки, `sleep`, `exit`,
  ввод с консоли, `async`/`await`. Такой скрипт не запустится, а сборщик его не упакует. Стандартные модули dypt
  (они подключаются через `import`) недоступны. Всё, что требует больше, — нативный код.
- Вызов, который думает дольше 0.5 с, выключает модификацию (сторож); остальные модификации со скриптами
  перезапускаются (их `загрузка()` выполняется заново) и получают сообщение.
- Пять ошибок в `тик()` выключают модификацию; причина — в окне.
- Все модификации вместе получают до 8 мс на тик симуляции; что не успело, ждёт следующего тика.
- До 64 геномов и 64 программ на модификацию, до 5000 изменений клеток за вызов; `mod.dpt` — до 64 КБ.

## Нативный код

Нативная модификация — это динамическая библиотека в `native/<платформа>/`:

| Платформа | Папка | Файл |
| --- | --- | --- |
| Windows x64 | `native/windows-x64/` | `.dll` |
| Android (телефон) | `native/android-arm64-v8a/` | `.so` |
| (ещё бывают) | `windows-arm64`, `android-x86_64`, `linux-x64`, `macos-arm64` | `.dll` / `.so` / `.dylib` |

Игра берёт папку своей платформы; модификация может нести библиотеки для нескольких платформ сразу. Если в папке
несколько библиотек (главная и её зависимости), главную называет строка `native <файл>` в `mod.txt`. Модификация
может быть одновременно скриптом и нативным кодом: тогда сначала загружается библиотека, потом скрипт.

**Статические библиотеки (`.a`, `.lib`) не подходят**: во время работы игра может загрузить только динамическую
библиотеку. Если у вас `.a`, слинкуйте её в свою `.dll`/`.so` (`gcc -shared`, `crate-type = ["cdylib"]`,
`go build -buildmode=c-shared` …). Сборщик откажется упаковывать `.a` и объяснит это.

### Интерфейс

Весь интерфейс — один заголовок на чистом C99: [`sdk/cellfap_mod.h`](../sdk/cellfap_mod.h). Никаких типов C++,
никакой памяти, которая переходит границу: всё передаётся структурами фиксированного размера и указателями на
функции, поэтому его понимает любой язык с C FFI.

Библиотека экспортирует две функции:

```c
#include "cellfap_mod.h"

CELLFAP_MOD_ENTRY uint32_t cellfap_mod_api_version(void) { return CELLFAP_MOD_API_VERSION; }

CELLFAP_MOD_ENTRY int cellfap_mod_load(const CellFapApi* api, CellFapMod* mod) {
    g_api = api;                       /* действителен до выгрузки */
    mod->after_step = my_after_step;   /* нужные обратные вызовы */
    mod->panel = my_panel;
    api->log(mod, "загружен");
    return CELLFAP_OK;                 /* иначе модификация не запустится */
}
```

`CellFapApi` — таблица функций игры, `CellFapMod` — структура модификации: часть полей заполняет игра (`id`,
`lib_dir`, `data_dir` — своя папка модификации для её файлов, `platform`), часть — модификация (обратные вызовы,
`user`, `panel_title`, `cell_types`, `events`).

**Версии.** `CELLFAP_MOD_API_VERSION` = 1. Новые функции дописываются только в конец `CellFapApi`, новые поля — в
конец `CellFapMod`; `api->struct_size` и `mod->struct_size` говорят, сколько знает другая сторона. Мод, собранный
для версии N, работает в любой игре с версией ≥ N; мод, которому нужна более новая версия, игра не загрузит и
скажет об этом.

### Обратные вызовы (точки изменения поведения)

Все необязательны (NULL — не нужен). Возвращают `CELLFAP_OK` (0); любое другое значение — ошибка (ниже).

| Вызов | Поток | Когда |
| --- | --- | --- |
| `cellfap_mod_load(api, mod)` | интерфейс | при включении; чашки ещё нет |
| `world_reset(mod, world)` | интерфейс сразу после загрузки; потом тот, что первым заметит | чашка, которую мод застал; потом — каждый раз, когда чашку заменили (новый опыт, файл, уровень) |
| `before_step(mod, world, &skip)` | симуляция | перед каждым тиком. `*skip = 1` — физика и биология игры в этом тике не выполняются (время идёт, `after_step` вызывается): **замена симуляции своей** |
| `cell_event(mod, world, event)` | симуляция | после тика: рождения (`CELLFAP_EVENT_BORN` — клетку поставили), деления (`DIVIDED`: `cell` — ребёнок в ячейке родителя с его id, `other` — второй), гибели (`DIED`: ячейка уже пуста, `id`, тип и место — погибшей). Только виды из маски `mod->events` |
| `cell_update(mod, world, cell)` | симуляция | после тика, для **каждой живой клетки типов из `mod->cell_types`** (`CELLFAP_TYPE_BIT(тип)`): своё поведение для типа клетки — двигать, кормить, менять сигналы, убивать |
| `after_step(mod, world)` | симуляция | после тика (после событий и `cell_update`): вся чашка |
| `settings_changed(mod, world)` | интерфейс | игрок поменял настройку из `mod.txt` (`world` может быть NULL) |
| `panel(mod, world, ui)` | интерфейс | каждый кадр, пока в окне «Модификации» открыта эта модификация: своя панель |
| `draw(mod, world, draw)` | интерфейс | каждый кадр, пока видна чашка: рисование поверх неё |
| `unload(mod)` | интерфейс | при выключении, после ошибки и при выходе из игры |

Маски `cell_types` и `events` игра перечитывает перед каждым тиком — модификация может менять их на ходу. Когда ни
одна модификация не просит событий, игра их не собирает; когда никто не просит `cell_update`, клетки не
перебираются: **без модов хуки ничего не стоят** (тест «Цена хуков»: меньше 0.001 % тика).

### Потоки

Игра вызывает модификацию из двух потоков — интерфейса и симуляции, — но **никогда одновременно**: каждый вызов
идёт, пока игра держит замок чашки. Своих замков модификации для данных игры не нужно.

Указатели `CellFapWorld*`, `CellFapUi*`, `CellFapDraw*` действительны **только во время того вызова**, которому
они переданы, и только в его потоке. Если библиотека сохранит указатель и позовёт функцию позже или из своего
потока, функция вернёт `CELLFAP_E_STATE` и ничего не тронет. Свои потоки модификация может запускать, но к чашке
из них обращаться нельзя (их работу забирайте в `after_step`). `log`, `message`, `setting` и прочие функции
модификации тоже работают только внутри обратных вызовов.

### Функции игры (`CellFapApi`)

Результаты: `CELLFAP_OK` 0, `CELLFAP_ERROR` −1, `CELLFAP_E_ARG` −2 (NULL, не число, неизвестное имя),
`CELLFAP_E_STATE` −3 (не сейчас), `CELLFAP_E_RANGE` −4 (номер вне диапазона или клетки там уже нет),
`CELLFAP_E_FULL` −5 (предел чашки), `CELLFAP_E_NOT_FOUND` −6. Числа, которые не числа (NaN, бесконечность),
отвергаются везде. Единицы: длина — мкм (центр чашки 0,0, y вверх), масса — нг, время — часы (тик = 1/400 ч),
углы — радианы, скорость — мкм за тик. Цвета — `0xRRGGBBAA` (`CELLFAP_RGBA(r,g,b,a)`).

**Сама модификация**

| Функция | Что делает |
| --- | --- |
| `log(mod, текст)` | строка в журнал модификации |
| `message(mod, текст)` | сообщение на экране |
| `set_error(mod, текст)` | причина, которую игрок увидит, если вызов вернёт ошибку |
| `setting(mod, ключ, запасное)` | настройка из `mod.txt`: число, флаг 0/1, номер варианта |
| `set_setting(mod, ключ, значение)` | изменить свою настройку (запоминается в `mods.ini`) |
| `mod_file(mod, путь, &данные, &размер)` | файл модификации (байты действительны до выгрузки) |
| `register_genome(mod, имя, текст)` | геном для браузера геномов и для `add_cell`; возвращает номер ≥ 0 (до 64) |
| `register_program(mod, имя, исходник)` | программа сигнальной клетки для редактора программ |
| `request_dish(mod, CELLFAP_DISH_SAVE / LOAD, имя)` | сохранить чашку в / открыть из `substrates/<имя>.substrate` (после вызова) |

| Функция | Что делает |
| --- | --- |
| `world_info(world, &info)` | тики, часы, клетки, номера ячеек клеток и связей, пища, геномы, число типов, радиус, свет дня, пределы |

| `get_link` / `cell_links` | связь (`a`, `b`; `b == -1` — приклеена к стеклу), связи клетки |
| `add_link(world, a, b, длина, жёсткость)` / `set_link` / `remove_link` | адгезины |

**Панель** (только внутри `panel`): `ui_text`, `ui_text_colored`, `ui_heading`, `ui_separator`, `ui_same_line`,

Подписи внутри панели должны различаться (`"Имя##2"` прячет хвост). Панель рисует игра своими виджетами — в
библиотеку не попадает ничего от Dear ImGui.

**Поверх чашки** (только внутри `draw`): `draw_line`, `draw_circle` (толщина 0 — залитый круг), `draw_text`.
Координаты — мировые (мкм), толщина — в пикселях экрана.

### Ошибки и безопасность нативного кода

- **Нативный код никогда не загружается сам.** Пока игрок не разрешил, библиотека даже не копируется в кэш. В окне
  у такой модификации раздел «Нативный код» с предупреждением, отпечатком SHA-256 и кнопкой «Разрешить нативный
  код…»; включение переключателем тоже сначала открывает вопрос: «Нативный код имеет полный доступ к компьютеру…».
- **Разрешение привязано к файлам.** В `settings/mods.ini` запоминается SHA-256 библиотек этой платформы
  (`native_sha256=…`). Другие файлы — другой отпечаток: игра пишет, что код изменился, и спрашивает снова. «Запретить
  нативный код» снимает разрешение.
- **Загрузка из копии.** Библиотеки копируются в `mods/.cache/<id>/<первые 16 знаков отпечатка>/` и загружаются
  оттуда — ровно те байты, которые проверены; файлы самой модификации не блокируются (папку можно пересобирать), на
  Android копия делается только для чтения.
- **Ошибка, которую мод вернул**, выключает его: вызывается `unload()`, библиотека выгружается, игрок видит
  сообщение с текстом из `set_error` (или код). Изменения чашки, сделанные до ошибки, остаются.
- **Падение или вечный цикл внутри нативного кода поймать нельзя** — ни на Windows, ни на Android нет переносимого
  способа пережить чужой сбой в своём процессе: игра закроется или зависнет вместе с модом. Сторож скриптов dypt
  нативный код не охраняет.
- Нативный код делает всё, что может сама игра: читает и пишет файлы, ходит в сеть, запускает программы. Поэтому —
  только из источников, которым доверяете.
- Скрипты dypt остаются в песочнице и разрешения не требуют.

### Сборка

Заголовок — `sdk/cellfap_mod.h`. Пример на C — `sdk/examples/c` (игра собирает его сама в
`build/<конфигурация>/mods/native_example/`), на Rust — `sdk/examples/rust`.

**C, MSYS2 (UCRT64), Windows**

```
gcc -std=c99 -O2 -shared -static-libgcc -I<CellFap>/sdk mod.c -o mod.dll
```

`-static-libgcc` — чтобы рядом не понадобилась `libgcc_s_seh-1.dll`. Строки в исходнике — в UTF-8 (так у gcc по
умолчанию).

**C / C++, MSVC**

```
cl /LD /O2 /utf-8 /I<CellFap>\sdk mod.c /Fe:mod.dll
```

В C++ функции экспортируются с `CELLFAP_MOD_ENTRY` (он уже содержит `extern "C"`); исключения C++ не должны вылетать
из обратных вызовов. `/utf-8` — чтобы русские строки дошли до игры в UTF-8.

**Rust**

```toml
[lib]
crate-type = ["cdylib"]
[profile.release]
panic = "abort"      # паника не должна разматываться в игру
```

```
cargo build --release                         -> target/release/<имя>.dll
cargo ndk -t arm64-v8a build --release        -> target/aarch64-linux-android/release/lib<имя>.so
```

Структуры повторите с `#[repr(C)]` в том же порядке полей (готовые объявления — в `sdk/examples/rust/src/lib.rs`;
можно и `bindgen` по заголовку). Функции — `#[no_mangle] pub extern "C"`.

**Zig**: `zig build-lib -dynamic -O ReleaseSafe mod.zig` с `@cImport(@cInclude("cellfap_mod.h"))`.
**Go**: `go build -buildmode=c-shared -o mod.dll` с `import "C"` и `//export cellfap_mod_load`; рантайм Go большой
(несколько МБ) и запускает свои потоки — к чашке из горутин обращаться нельзя. **Odin, Nim, Pascal, D** — любой
язык, который умеет экспортировать функции C и описывать C-структуры.

**Android.** Собирайте NDK под `arm64-v8a`, `minSdkVersion` ≤ 26, без зависимостей кроме системных (`libc`, `libm`,
`libdl`, `liblog`, `libandroid`); C++ — со статическим `libc++` (`-static-libstdc++` или `ANDROID_STL=c++_static`).
Например: `aarch64-linux-android26-clang -shared -fPIC -O2 -I<CellFap>/sdk mod.c -o libmod.so`.

**Android и dlopen.** Папка `mods` на телефоне лежит во внутреннем хранилище приложения
(`/data/user/0/<пакет>/files/mods`), и кэш библиотек — там же. Ограничение W^X Android 10+ (targetSdk ≥ 29) запрещает
приложению `exec()` файлов из своей папки, но не `dlopen()` библиотек: загрузка `.so` из внутреннего хранилища
разрешена (у игры targetSdk 35). Android 14+ требует, чтобы динамически загружаемый код был только для чтения, —
игра ставит копии права `0500` до загрузки. С общей памяти (`/sdcard`, `Android/data`) библиотеки не загрузились бы
(она смонтирована `noexec`), поэтому игра всегда грузит копию из внутреннего кэша. Если библиотеке нужны свои
`.so`-зависимости, положите их рядом: игра загружает их раньше главной. **На телефоне это ещё не проверено** — если
`dlopen` откажет, в окне будет его текст ошибки.

## Шейдеры

Модификация может заменить стадии четырёх конвейеров, которыми игра рисует сцену:

| Слот | Что рисует | Файлы |
| --- | --- | --- |
| `dish` | чашку и воду (полноэкранный треугольник, 3 вершины, без входов) | `shaders/dish.vert.spv`, `shaders/dish.frag.spv` |
| `cell` | клетки (6 вершин на клетку, по экземплярам) | `shaders/cell.vert.spv`, `shaders/cell.frag.spv` |
| `line` | адгезины и нити (6 вершин на отрезок) | `shaders/line.vert.spv`, `shaders/line.frag.spv` |
| `particle` | пищу, вирусы, облака, вспышки (6 вершин на частицу) | `shaders/particle.vert.spv`, `shaders/particle.frag.spv` |

Можно положить только одну стадию (например, `cell.frag.spv`) — вторая останется встроенной. Игра загружает **только
SPIR-V** (`.spv`). Исходники GLSL (`cell.frag` и т. п.) можно класть рядом: сборщик (`modpack` и кнопка «Собрать
.cfmod») компилирует их `glslc` (из Vulkan SDK: `$VULKAN_SDK`, `PATH`, путь из настроек «Разработчик» или переменная
`CELLFAP_GLSLC` для `modpack`), если `.spv` нет или он старше исходника. Без компилятора нужен готовый `.spv`.
**На телефоне компилятора нет** — только `.spv`.

Шейдеры включённой модификации действуют, пока она включена; выключили — вернулись встроенные. Слот может занимать
только одна модификация: у второй в окне написано, с кем конфликт. Модуль, который Vulkan не принял (не SPIR-V,
другие входы или push-константы), не ломает игру: остаётся встроенный шейдер, а в окне — причина.

### Интерфейс шейдеров

Исходники встроенных шейдеров — в папке `shaders/` игры (и в панели «Разработчик» → «Шейдеры»); проще всего взять
нужный и изменить. Общие объявления — `shaders/common.glsl`: положите его копию рядом со своими исходниками и
подключайте `#include "common.glsl"` (`#extension GL_GOOGLE_include_directive : require`).

**Push-константы** (все стадии, 64 байта):

```glsl
layout(push_constant) uniform PC {
    vec4 cam;     // xy — центр камеры (мир), zw — масштаб мир -> clip (worldToClip)
    vec4 params;  // x — время, с; y — мировых единиц в пикселе; z — радиус чашки; w — уровень света 0..1
    vec4 extra;   // x — направление света (рад); y — прозрачность сетки; z — разброс света; w — тема (1 классическая, 0 тёмная)
    vec4 extra2;  // x — ночь (0 день .. 1 глубокая ночь)
} pc;
```

**Входы вершин** (binding 0, по экземплярам):

| Слот | location: тип — смысл |
| --- | --- |
| `cell` | 0 `vec2` центр; 1 `float` радиус; 2 `float` угол; 3 `vec4` цвет (RGBA8 unorm); 4 `uint` тип \| флаги<<8 \| зерно<<16 (флаги: 1 выбрана, 2 заражена, 4 голодает, 8 под курсором, 16 фантом, 32 режим редактора); 5 `float` p0; 6 `float` p1 (параметры типа); 7, 8 `uvec4` форма: 32 луча по байту, радиус = 0.4 + байт/255 |
| `line` | 0 `vec2` A; 1 `vec2` B; 2 `float` полуширина (мир); 3 `vec4` цвет; 4 `float` перетяжка 0..0.9 |
| `particle` | 0 `vec2` центр; 1 `float` радиус; 2 `vec4` цвет; 3 `uint` вид (биты 0–7: 0 пища, 1 вирус, 2 кольцо, 3 свечение, 4 диск, 8 облако, 9 искра; 8–15 зерно); 4 `float` угол |
| `dish` | нет входов: `gl_VertexIndex` 0..2 |

**Переходы между стадиями** встроенных шейдеров (если заменяете одну стадию, держите их такими же):

| Слот | vert -> frag |
| --- | --- |
| `cell` | 0 `vec2 vLocal`; 1 `flat vec4 vColor`; 2 `flat uint vTypeFlags`; 3 `flat vec3 vParams` (радиус, p0, p1); 4 `vec2 vWorldDir`; 5, 6 `flat uvec4 vShape0/1`; 7 `vec2 vWorld`; 8 `flat vec2 vCenter` |
| `line` | 0 `vec2 vUV`; 1 `flat vec4 vColor`; 2 `flat vec3 vLenW` |
| `particle` | 0 `vec2 vLocal`; 1 `flat vec4 vColor`; 2 `flat uint vKind`; 3 `flat float vRadiusPx` |
| `dish` | 0 `vec2 vWorld` |

Выход фрагментного шейдера — `layout(location = 0) out vec4 outColor`, **цвет, умноженный на прозрачность**
(premultiplied alpha; смешивание `ONE, ONE_MINUS_SRC_ALPHA`), у `dish` — непрозрачный.

Пример — `sdk/examples/shader_tint` («Сиреневые клетки»): встроенный `cell.frag`, у которого `main()` переименован
в `cellfapBaseMain()`, и новая `main()`, которая зовёт его и подкрашивает результат. Игра собирает этот пример в
`build/<конфигурация>/mods/shader_tint/`.

### Шейдеры и безопасность

Шейдер — код для видеокарты: он не может читать файлы, ходить в сеть или трогать память игры, а Vulkan проверяет
модуль при создании конвейера. Худшее, что он может, — очень медленный или бесконечный цикл на GPU: картинка
зависнет, драйвер сбросит устройство (на Windows — TDR через ~2 с), игра может закрыться. Это неприятно, но не
опасно для данных, поэтому **отдельного разрешения шейдеры не требуют** — они включаются вместе с модификацией, а
выключение модификации возвращает встроенные.

## Сборка .cfmod

В окне — кнопка «Собрать .cfmod» у модификации-папки: файл появится в папке `exports` (не в `mods` — там он стал бы
второй модификацией с тем же `id`), на телефоне сразу откроется «Поделиться». Или из командной строки (собирается
вместе с игрой):

```
modpack mods/example                  собрать example.cfmod в текущей папке
modpack mods/example out.cfmod        собрать в свой файл
modpack --check mods/example          проверить, ничего не записывая
modpack --list example.cfmod          что внутри: картинка, нативный код (платформы, главная библиотека, SHA-256), шейдеры, assets
modpack --unpack example.cfmod папка  распаковать
```

Сборщик проверяет `mod.txt` (так же, как игра), `mod.dpt` (запрещённые функции), `native/` (нет ли статических
библиотек; какая библиотека главная), `shaders/` (компилирует исходники, проверяет, что `.spv` — SPIR-V). Собрать
`.cfmod` можно и любым ZIP-архиватором — игра прочитает.

## Примеры

- `mods/example` — скрипт: геном «Розовая водоросль», программа «Мигалка», пищевой дождь с настройками и свет,
  обходящий чашку по кругу.
- `sdk/examples/c` — «Водоворот», нативный мод на C: водоворот в `after_step`, лечение фагоцитов в `cell_update`,
  счёт рождений и гибелей в `cell_event`, остановка физики в `before_step`, своя панель и рисование вихря.
- `sdk/examples/rust` — «Дыхание света», нативный мод на Rust: свет чашки «дышит», панель считает клетки по типам.
- `sdk/examples/shader_tint` — «Сиреневые клетки», модификация только из шейдера, с картинкой и `assets/`.

```dypt
дождей = 0

function загрузка() {
    добавить_геном("Розовая водоросль", "genomes/pink_alga.genome.txt")
    добавить_программу("Мигалка", "programs/blinker.dpt")
}

function тик(состояние) {
    if настройка("дождь") {
        for k = 1 to настройка("порций") {
            добавить_пищу((случайное() - 0.5) * 400, (случайное() - 0.5) * 400, 0.3)
        }
        дождей = дождей + 1
    }
}
```

Правите `mod.dpt` или пересобрали библиотеку — нажмите «Перезапустить» в окне: файлы перечитаются с диска (новую
библиотеку игра попросит разрешить заново).
